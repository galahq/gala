# Requirements Archive: v1.0 Upgrade Stabilization

**Archived:** 2026-05-12
**Status:** SHIPPED
**Audit:** `.planning/milestones/v1.0-MILESTONE-AUDIT.md`

The milestone audit found all v1 requirements satisfied: 32/32 requirements, 10/10 phases, 6/6 integration checks, and 8/8 end-to-end flows. Remaining issues are artifact consistency tech debt, not product blockers.

## v1 Requirements

### Foundation

- [x] **FOUND-01**: Developer can run or connect to the Rails app at `localhost:3000` for route QA.
- [x] **FOUND-02**: Application layout loads global JavaScript and CSS without duplicating BlueprintJS styles or breaking prior page-specific assumptions.
- [x] **FOUND-03**: BlueprintJS compatibility behavior supports legacy `.pt-*` expectations and current `.bp4-*` classes where the app still depends on old styling.
- [x] **FOUND-04**: QA gate records route group, representative URLs, browser result, console/network issues, automated tests run, and commit hash before advancing.

### Public Routes

- [x] **PUB-01**: Error pages `403`, `404`, `422`, and `500` render without broken layout or missing styles.
- [x] **PUB-02**: Health and diagnostic endpoints `up` and `runtime/stats` keep expected response formats and authorization behavior.
- [x] **PUB-03**: Locale redirect routes preserve path/format behavior without causing frontend asset or layout regressions.
- [x] **PUB-04**: Legacy published `/read/...` redirects remain intact.

### Catalog

- [x] **CAT-01**: Root catalog route `/` renders catalog UI with expected Blueprint input, button, menu, and non-ideal-state styling.
- [x] **CAT-02**: Catalog catch-all routes continue to hand off to React Router without Rails routing regressions.
- [x] **CAT-03**: Catalog library and language routes render and respond correctly.
- [x] **CAT-04**: Catalog search UI remains visually usable and does not show console/runtime errors.

### Cases

- [x] **CASE-01**: Case index, show, create, edit, update, destroy, copy, delete confirmation, archive, settings, translations, and library routes keep existing behavior.
- [x] **CASE-02**: Case React Router suffix routes under `/cases/:case_slug/...` render the same case shell and preserve nested route behavior.
- [x] **CASE-03**: Case overview/editor Blueprint controls such as buttons, dialogs, editable text, popovers, tags, switches, and inputs retain acceptable spacing, icons, and interaction states.
- [x] **CASE-04**: Case comments, forums, comment threads, activities, locks, taggings, podcasts, pages, cards, edgenotes, quizzes, stats, and Wikidata links remain functional after style fixes.

### Reader Workflows

- [x] **READ-01**: Reader Devise routes for sign in, registration, confirmation, and session handling render without layout or Blueprint regressions.
- [x] **READ-02**: Profile, persona, reader index, terms-of-service edit/update, roles, enrollments, magic link, and my-cases routes keep expected behavior.
- [x] **READ-03**: Reading-list, saved-reading-list, save/unsave, library, library management, case-library-request, and managership routes remain styled and usable.

### Deployments and Integrations

- [x] **DEP-01**: Deployment index, show, new, create, edit, update, and submissions routes remain functional and styled.
- [x] **DEP-02**: Canvas deployment and LTI content-item/auth strategy routes preserve CSRF-skip validation boundaries and do not regress visual or redirect behavior.
- [x] **DEP-03**: SPARQL/Wikidata routes retain current behavior while any discovered malformed-input regressions are documented for separate fix scope unless directly blocking QA.

### Admin and Operations

- [x] **ADM-01**: Admin root and Administrate resources render with usable styling after the global asset loading change.
- [x] **ADM-02**: Admin case copy and nested admin resources keep expected authorization and routing behavior.
- [x] **ADM-03**: Sidekiq web route remains editor-only and is not broken by layout/style changes.

### Regression Gates

- [x] **QA-01**: Each phase includes a route checklist derived from `config/routes.rb`.
- [x] **QA-02**: Each phase performs browser QA on representative routes with console and network checks.
- [x] **QA-03**: Each phase runs targeted automated tests where practical, choosing from `bundle exec rspec`, `./run-rspec.sh`, `bundle exec rake test:unit`, and `yarn test`.
- [x] **QA-04**: Each phase commits only after the current route group passes QA or has documented, non-blocking exceptions.

### Cleanup

- [x] **CLEAN-01**: Remove or consolidate duplicate BlueprintJS compatibility CSS/JS once all route groups pass.
- [x] **CLEAN-02**: Remove dead imports, stale pack assumptions, unused compatibility shims, and misleading comments introduced during the upgrade.
- [x] **CLEAN-03**: Final pass runs broad regression checks and updates documentation or planning notes with remaining known risks.
