# Phase 05 Plan 01: Nested Content Route and Mutation Baseline

<objective>
Stabilize the reader/editor-visible nested case surfaces for comments, comment threads, pages, cards, case elements, edgenotes, podcasts, forums, and activities by deriving route coverage from `config/routes.rb`, browser-QAing authenticated nested widgets through mock Google login, adding request coverage for representative JSON mutations, and applying only verified Blueprint compatibility fixes.
</objective>

<must_haves>
## Truths

- D-01: Use broad read-only visual/API coverage plus a small number of reversible writes.
- D-02: Clean up disposable mutation data in the same QA pass when UI/API supports deletion.
- D-03: Browser writes are limited to lower-risk reversible interactions; pages, cards, podcasts, edgenotes, and quizzes are read/API/spec-first unless a safe need emerges.
- D-04: Use existing local cases/readers first and document substitutions; do not add seed infrastructure.
- D-05: Start Phase 5 QA with reader/editor-visible surfaces: comments/conversation, pages/cards, edgenotes, and podcasts.
- D-07: Protected route groups require `/readers/sign_in` then clicking `a.oauth-icon-google` before visual assertions.
- D-08: JSON-only or hard-to-reach routes are tested with request specs/direct API checks beside related UI surfaces.
- D-13: Visual gates require usable, nonblank surfaces with no new blocking console/network errors and acceptable Blueprint dialogs, popovers, toasts, buttons, inputs, tags, loading/progress.
- D-16: Preserve old Gala/Blueprint 2-era density and behavior; do not redesign to Blueprint 4 defaults.

## UI Contract

- Preserve `.pt-*` classes and add `.bp4-*` companions only when a verified Phase 5 surface needs static class coverage.
- Do not import Blueprint CSS from route packs or duplicate Blueprint CSS.
- Inspect likely legacy targets: `NewUnattachedCommentButton.jsx`, `Response.jsx`, `CommentThreadLocation.jsx`, edgenote editor dialogs/forms, page/card editor surfaces, and podcast forms.
- Record console/network findings as blocking, accepted noise, or follow-up risk in `05-QA.md`.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-05-01 | medium | Protected nested write routes could pass visual QA while JSON behavior or authorization regresses. | Add/request-run representative specs for comment threads/comments/forums and any touched nested controller behavior. |
| T-05-02 | medium | Browser QA could mutate important local case data. | Limit writes to reversible low-risk interactions, clean up immediately, and document all temporary writes. |
| T-05-03 | low | Broad Blueprint class changes could regress prior phase route groups. | Only apply paired-class fixes where browser QA proves a nested surface regression. |
| T-05-04 | low | Existing local data variance could hide missing route coverage. | `05-QA.md` must record selected slugs, substitutions, skipped routes, and supplemental specs. |
</threat_model>
