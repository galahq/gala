# Phase 05 Plan 03: Quiz and Submission Route Stabilization

<objective>
Stabilize Phase 5 quiz and submission routes through read/API/spec-first checks, authenticated browser inspection of quiz editor/show widgets where local data allows, and narrow fixes for verified JSON or Blueprint form/dialog regressions.
</objective>

<must_haves>
## Truths

- D-03: Quizzes are read/API/spec-first unless a safe need emerges.
- D-06: Quiz flows are inspected after stats/map and before Wikidata/SPARQL.
- D-07: Protected quiz route groups require mock Google login through `a.oauth-icon-google`.
- D-08: JSON-only or hard-to-reach quiz routes are tested with request specs/direct API checks beside related UI.
- D-10: Known concerns discovered during QA are documented unless they block route stabilization.
- D-13: Quiz visual gates require usable/nonblank surfaces and acceptable Blueprint form/button/dialog states.
- D-15: Deeper interaction checks are required for quiz editor/show flow.
- D-16: Preserve existing Gala/Blueprint 2-era density and copy.

## UI Contract

- Suggested quiz list/editor, quiz show, question/option editor, destructive confirmation, and submission controls retain existing Blueprint form and button behavior.
- Preserve existing translated copy and destructive action names.
- Do not depend on Selenium feature specs while local driver initialization remains blocked.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-05-09 | medium | Quiz create/update/destroy routes could alter shared local case data during browser QA. | Prefer specs/API checks; only perform browser writes if reversible and cleaned up. |
| T-05-10 | medium | Authorization around suggested quiz editing/submissions could regress unnoticed. | Read `quiz_policy_spec.rb`, run policy/service specs, and record protected route auth state in QA. |
| T-05-11 | low | Legacy feature specs could block execution because Selenium is currently broken. | Use request/controller/service/Jest and Playwright MCP instead of Selenium feature specs. |
| T-05-12 | low | Blueprint 4 defaults could loosen old quiz editor density. | UI fixes must be narrow and tied to visible quiz surface regressions. |
</threat_model>
