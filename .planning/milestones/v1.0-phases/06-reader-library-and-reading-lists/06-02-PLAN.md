# Phase 06 Plan 02: Reading-List Editor and Save Flow Stabilization

<objective>
Stabilize reading-list new/edit/show/save/unsave flows through a disposable browser-created reading list, focused Jest/request coverage for React hidden inputs and Rails nested attributes, and narrow visual fixes for the reading-list editor, item chooser, item list, and save controls.
</objective>

<must_haves>
## Truths

- D-05: Use a disposable browser-created reading list for the main visual and functional reading-list QA path.
- D-06: Exercise create, edit, item selection, save/unsave, and delete/cleanup when UI and local data make cleanup practical.
- D-07: Use existing local cases/enrollments first for list item selection; do not build broad seed infrastructure.
- D-08: Cover edge cases and hidden-field behavior with focused Jest/request specs around `app/javascript/reading_list` and nested `reading_list_items_attributes`.
- D-13: Give closest Blueprint parity attention to the reading-list editor, item chooser, hidden-form-backed item list, and save/unsave controls.
- D-16: Add `.bp4-*` companions or scoped compatibility styles only where the Phase 6 surface visibly needs them.
- D-19: Check browser console and network errors before marking the route group complete.
- D-20: Classify existing React 16 warnings and unrelated browser noise unless visible behavior breaks.
- D-21: Use Docker Compose for app tests where host Ruby is mismatched.

## UI Contract

- Reading-list new/edit must keep Rails form and React editor usable within the existing `md-master`/`md-detail` layout.
- Title, description, item chooser, item notes, ordering/removal, hidden inputs, and submit controls must remain usable.
- Reading-list show must preserve title, description, reader identity, case thumbnails, notes, enroll buttons/tags, edit/delete actions, and save/unsave controls.
- The main visual focal point for Phase 6 is the reading-list editor and item chooser.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-06-05 | medium | React editor state could render correctly but submit incorrect nested attributes. | Run/extend `HiddenFormInputs.test.jsx` and request specs for `reading_list_items_attributes`. |
| T-06-06 | medium | Browser QA could leave disposable reading-list data behind. | Use a clearly named disposable list and delete it or document cleanup result in `06-QA.md`. |
| T-06-07 | medium | Save/unsave UI could toggle visually while server state fails. | Check network responses for POST/DELETE `/reading_lists/:uuid/save` and run save request specs. |
| T-06-08 | low | Fixing the editor could introduce a new React pattern into legacy React 16 code. | Reuse existing React/Stimulus/Orchard patterns; do not introduce new form libraries. |
</threat_model>
