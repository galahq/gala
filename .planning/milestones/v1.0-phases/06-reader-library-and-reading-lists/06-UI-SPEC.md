## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, note borders, inline icon-to-label spacing |
| sm | 8px | Compact form spacing, reader metadata gaps, note padding |
| md | 16px | Default grid gaps, form groups, reading-list info separation |
| lg | 24px | Section padding and medium surface separation |
| xl | 32px | Reading-list actions and item note separation |
| 2xl | 48px | Major section breaks inside long account/library pages |
| 3xl | 64px | Mobile reading-list item action separation and page-level breaks |

Exceptions: existing legacy dimensions may remain when already present and visually correct: `.devise-card` width `22em`, case thumbnail/table dimensions, library logo image width `43px`, library request card width `250px`, Blueprint default control heights, and responsive breakpoint `$mobileCutoff: 513px`. New Phase 6 fixes must use the declared scale unless matching an existing nearby legacy value is required for parity.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#02284B` / tinted `#1d3f5e` dark Gala shell | Page background, dark master/detail panels, admin headers, reading-list show surfaces |
| Secondary (30%) | `#EBEAE4` and Blueprint neutral surfaces | Forms, cards, tables, callouts, input backgrounds, library table rows |
| Accent (10%) | `#7351D4` | Devise card border/text family, profile/persona accent surfaces, OAuth sign-in emphasis where existing styles use the purple family |
| Destructive | `#B51957` / Blueprint danger intent | Delete reading list, unsave saved list, delete library, remove manager, remove case from library, reject case-library request |

Accent reserved for: Devise card border and text, profile/persona accent states already using the purple family, and existing branded sign-in/account surfaces. Do not apply the accent to every interactive element. Primary actions should continue to use Blueprint intent classes (`pt-intent-primary`, `bp4-intent-primary`, `pt-intent-success`, `bp4-intent-success`) where the route already does so.

Destructive color is reserved for destructive actions only and must appear through existing Blueprint danger classes plus any necessary `.bp4-*` companion classes.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Save Reading List` for save/unsave flow; `Create Reading List` or existing Rails submit copy for new-list form; `Sign in` for Devise session form |
| Empty state heading | Use existing localized empties: `No requests yet`, `No cases yet`, or `No search results` depending on route |
| Empty state body | For reading-list item chooser, keep `Search for a case to add...`; for library/request management, show the existing localized empty tag with no extra explanatory marketing copy |
| Error state | Use existing Rails/Devise form error summaries and flash copy; errors must state the problem and keep the user on the same form with corrected Blueprint input/error styling |
| Destructive confirmation | Delete Reading List: `Are you sure you want to delete this reading list? If you do, it will be removed from the libraries of anyone you’ve shared it with.` |

Additional destructive confirmations:

| Action | Confirmation Copy |
|--------|-------------------|
| Delete library | Existing `libraries.destroy.are_you_sure` locale copy |
| Remove manager | `Are you sure you want to remove %{name} as a manager of this library?` |
| Remove case from library | `Are you sure you want to remove case ’%{name}’ from the library?` |
| Remove saved reading list | Icon-only unsave button uses aria label `Remove reading list from library`; no browser confirm required unless already implemented |
| Accept/reject case-library request | Use existing accept/reject confirmation locale copy |

Do not add tutorial text, hero copy, or new explanatory panels. Phase 6 copy should preserve current localized labels and only repair missing/error/aria copy when needed for usability.

## Interaction Contract

### Route Coverage

Use `config/routes.rb` as the route source of truth. Browser QA must sample:

| Surface | Required Visual/Interaction Check |
|---------|-----------------------------------|
| Devise sign-in | `/readers/sign_in` renders the compact `devise-card`, full-width email/password inputs, remember-me checkbox, primary sign-in button, Google OAuth button with 16px logo, links, flash/errors, and focus states |
| Public Devise form | At least one of sign-up, password reset, confirmation, or unlock renders with the same card density and Blueprint form styling |
| Mock authenticated account | Sign in by clicking `a.oauth-icon-google`; verify profile/TOS surfaces after authentication |
| Profile/persona/TOS | Forms retain label/input grouping, errors, primary CTA, and TOS continue button without density drift |
| Reading-list new/edit | Rails form and React editor render side-by-side in `md-master`/`md-detail`; title, description, item chooser, item notes, ordering/removal, hidden inputs, and submit all remain usable |
| Reading-list show | Reading-list title, description, reader identity, case thumbnails, notes, enroll buttons/tags, edit/delete actions, and save/unsave controls retain Blueprint spacing and responsive behavior |
| Libraries | Library table, logos, catalog links, create form, edit/delete icon buttons, and `On Home Page` tags remain aligned and readable |
| Library management | Manager list, add-manager form, requests, cases, remove buttons, confirmations, and authorization-gated affordances remain visible when policies allow them |
| Saved reading lists/enrollments/my cases | JSON and protected-route behavior must remain unchanged; browser UI checks can be representative where surfaces are data-light |
| Magic link | Entry surface preserves existing button/copy and route behavior |

### Priority Order

1. Reading-list editor, item chooser, hidden-form-backed item list, and save/unsave controls.
2. Auth/profile forms: density, inputs, labels, button sizing, OAuth presentation, flashes, and TOS flow.
3. Library and management screens: tables/lists, management buttons, destructive controls, confirmation flows, and visible authorization affordances.

### Blueprint Compatibility

- Preserve legacy `.pt-*` classes where already present.
- Add `.bp4-*` companions only when a Phase 6 surface visibly needs Blueprint 4 compatibility.
- Do not duplicate global Blueprint CSS.
- Do not add route-specific shims until browser QA confirms a visible Phase 6 regression.
- Icon-only buttons must retain aria labels and Blueprint icon classes.
- Destructive icon buttons must use minimal/danger styling and confirmation where existing behavior expects it.

### Responsive Behavior

- At widths below the existing `$mobileCutoff: 513px`, reading-list items must use the existing two-column layout, notes span the available width, and action controls move below the item without overlapping notes or thumbnails.
- Text inside buttons and tags must not wrap into unreadable icon/text collisions.
- Library management request cards may wrap, but each request card must keep its title, cover, and action button readable.

### QA Evidence

Before marking Phase 6 visually complete, browser QA must record representative route, signed-in state, expected result, visible result, console issues, network issues, and whether any local-data gap was supplemented by specs.

Known non-blocking noise may be classified according to `06-CONTEXT.md` D-20. Visible behavior breaks, missing Blueprint styles, broken save/unsave state, hidden input failures, and authorization affordance regressions are blocking.
