# Phase 06 Plan 03: Library, Reader Management, and Phase QA Gate

<objective>
Stabilize library, managership, case-library-request, reader-management, enrollment, editorship, my-cases, roles, and final Phase 6 QA gate behavior after auth/profile and reading-list foundations are covered.
</objective>

<must_haves>
## Truths

- D-09: Use the mock admin session for reachable library, managership, case-library-request, reader, enrollment, editorship, and my-cases surfaces.
- D-10: If local data lacks manager-accessible libraries or pending case-library requests, document the browser gap and supplement manager/request paths with controller/request specs.
- D-11: Anonymous redirect behavior is not sufficient for manager-focused routes when visible affordance or authorization behavior is central.
- D-12: Create or modify local data only when narrow, disposable, and safer than broad seed setup.
- D-15: Library and management screens are third visual priority: verify tables/lists, management buttons, destructive controls, confirmation flows, and visible authorization affordances.
- D-17: `config/routes.rb` remains the route coverage source of truth.
- D-19: Browser console and network errors must be checked before marking the route group complete.
- D-21: Docker Compose is the preferred runtime for targeted app tests.

## UI Contract

- Libraries must keep library table, logos, catalog links, create form, edit/delete icon buttons, and `On Home Page` tags aligned and readable.
- Library management must keep manager list, add-manager form, requests, cases, remove buttons, confirmations, and authorization-gated affordances visible when policies allow them.
- Saved reading lists, enrollments, and my-cases JSON/protected-route behavior must remain unchanged; browser UI checks can be representative where surfaces are data-light.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-06-09 | medium | Manager-only routes could be marked covered by anonymous redirects or empty local pages. | Use mock admin browser state and supplement missing local manager data with request/controller specs. |
| T-06-10 | medium | Library/managership destructive actions could expose or remove unauthorized records. | Verify Pundit/request behavior for manager/request branches and inspect visible destructive controls. |
| T-06-11 | low | Empty local data could hide table/button Blueprint regressions. | Record local-data gaps and inspect any reachable table/list surface; specs cover behavior when visual data is thin. |
| T-06-12 | low | Phase could advance without consolidated QA evidence. | Final task requires `Plan 03 status: PASS` or `BLOCKED`, route checklist, browser console/network, and test command evidence. |
</threat_model>
