# Phase 08 Plan 01: Admin Route Checklist, Data Setup, and Auth Boundary Coverage

<objective>
Create the Phase 8 route checklist and evidence scaffold from `config/routes.rb`, build a reproducible representative admin dataset, and add focused request/controller coverage for editor-only admin access, `admin/cases/:id/copy`, `admin/ahoy/events`, and `/sidekiq`.
</objective>

<must_haves>
## Truths

- D-01: Use a representative browser sweep instead of visiting every admin resource individually.
- D-03: Empty admin pages are acceptable if the shared shell renders correctly, but each major admin slice should include at least one populated representative resource.
- D-04: Keep admin and operational auth/authorization checks mostly spec-driven.
- D-05: Use only minimal protected-surface browser QA on admin/editor-only routes; rely on request/controller specs for anonymous and non-editor denial behavior.
- D-06: Use a deliberate mix of request and controller specs based on existing nearby coverage and the specific behavior under test.
- D-10: Treat `admin/cases/:id/copy` as the primary mutation path to exercise in this phase.
- D-12: Verify `/sidekiq` as editor-only and perform only a landing-page smoke test once inside.
- D-13: Seed a small representative admin dataset up front so browser QA can inspect populated admin tables and show pages.
- D-14: Prefer factories/spec-backed setup for the seeded dataset.
- D-16: `config/routes.rb` remains the source of truth for route coverage.
- D-18: Keep fixes narrow and route-driven; avoid broad restyling or permission model changes unless a verified admin regression requires it.

## UI Contract

- `08-QA.md` must derive its checklist from actual Phase 8 routes in `config/routes.rb`, not from unused admin controllers or dashboards.
- The representative admin set should center on route-backed resources. If the discussed `libraries` anchor is not exposed under `/admin`, record the route mismatch and substitute one route-backed admin resource in the checklist.
- Phase 8 evidence must clearly separate spec-backed auth/access results from browser-visible admin-shell results.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-08-01 | medium | Phase 8 could silently assume nonexistent admin routes and produce false route coverage. | Build the checklist strictly from `config/routes.rb` and record any discussed-vs-routed substitution in `08-QA.md`. |
| T-08-02 | medium | Admin and Sidekiq authorization could regress while browser checks only cover happy-path editor access. | Add focused request/controller coverage for anonymous and non-editor denial behavior. |
| T-08-03 | medium | The custom admin case copy route could break redirect or cloning behavior while shared admin pages still render. | Add dedicated copy-route coverage and include it as a named checklist item. |
| T-08-04 | low | Representative browser QA could be misleading if all sampled admin resources are empty. | Create a small reproducible admin dataset using factories so at least one populated route exists in each major sampled slice. |
</threat_model>
