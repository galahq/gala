# Phase 08 Plan 02: Representative Admin Browser QA, Copy Flow, and Final Gate

<objective>
Use the Plan 01 dataset and route checklist to browser-QA the representative admin shell, validate the custom copy path and Ahoy ordering, smoke-test editor access to `/sidekiq`, and finalize Phase 8 QA evidence with only narrow route-backed fixes.
</objective>

<must_haves>
## Truths

- D-01: Use a representative browser sweep instead of visiting every admin resource individually.
- D-03: Empty admin pages are acceptable if the shared shell renders correctly, but each major admin slice should include at least one populated representative resource.
- D-05: Use only minimal protected-surface browser QA on admin/editor-only routes.
- D-07: Prioritize case admin pages and custom action surfaces for the closest visual parity review.
- D-08: Shared Administrate shell issues still matter, but broad polish across every generic resource should stay secondary to case/admin action routes.
- D-09: `admin/ahoy/events` should receive shared-shell coverage plus an explicit newest-first ordering check.
- D-10: Treat `admin/cases/:id/copy` as the primary mutation path to exercise in this phase.
- D-12: Verify `/sidekiq` as editor-only and perform only a landing-page smoke test once inside.
- D-17: Protected browser QA should use the local sign-in flow at `/readers/sign_in` and the mock Google button `a.oauth-icon-google`.
- D-18: Keep fixes narrow and route-driven.
- D-19: Existing unrelated console noise or local dev-server noise should be classified rather than treated as blocking unless visible behavior breaks.

## UI Contract

- Admin root and representative admin resources must render the existing toolbar, search shell, table density, pagination, and show-page structure without obvious Blueprint compatibility regressions.
- Case admin pages and the copy affordance are the highest visual priority.
- `/sidekiq` needs only a landing-page smoke check once editor access is confirmed.
- Any fix should stay in the owning admin view/controller unless browser QA proves a broader shared-shell defect.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-08-05 | medium | Shared admin shell regressions could persist across multiple resources if only the copy route is checked. | Browser-QA the admin root plus the agreed representative route-backed resources. |
| T-08-06 | medium | The copy action could mutate data unexpectedly or redirect incorrectly in-browser even if specs pass. | Use a copy-safe case from Plan 01 and record the resulting redirect or cloned destination in `08-QA.md`. |
| T-08-07 | medium | Ahoy event ordering could regress silently because the page still renders. | Explicitly inspect newest-first ordering in the representative Ahoy events sample. |
| T-08-08 | low | Sidekiq browser QA could expand into unsupported infra validation. | Limit the browser check to the landing page and classify anything beyond that as out of scope. |
</threat_model>
