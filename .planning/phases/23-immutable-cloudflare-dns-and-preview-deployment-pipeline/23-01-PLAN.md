# Plan 23-01: Cloudflare DNS, Immutable Assets, and Minimal Deploy Workflow

## Goal

Add SST-owned Cloudflare DNS and release-aware deployment mechanics without changing Heroku `.com` production.

## Tasks

1. Update `infra/sst.config.ts`.
   - Add Cloudflare provider configuration.
   - Derive release ID, preview host, base URL, and asset prefix from CI environment.
   - Switch app edge distribution to SST CDN so custom domain DNS and certificates are managed through SST.
   - Inject release metadata and release-scoped `ASSET_HOST` into Rails runtime.

2. Update `.github/workflows/deploy.yml` and `scripts/deploy-sst.sh`.
   - Reduce workflow inputs to the approved five.
   - Gate execution to write/maintain/admin contributors.
   - Generate release IDs and preview URLs in workflow.
   - Upload static assets to immutable S3 prefixes and retain 10 release namespaces per stage.
   - Use one shared SST Router CloudFront distribution for `learngala.dev`, `dev.learngala.dev`, and `*.dev.learngala.dev`; keep the validated stage app CDN unaliased for rollback/performance comparison until the Router is proven stable.
   - Support cache invalidation, preview PR comments, production releases, and hard-coded `user_data` hooks.

3. Add release and repository safety files.
   - Add CODEOWNERS for deployment-sensitive paths.
   - Add SECURITY.md and RELEASE.md.
   - Surface release URL metadata from `app/views/layouts/application.html.erb`.

4. Update GSD and codebase docs.
   - Add Phase 23 requirements and roadmap coverage.
   - Update `.planning/codebase/` and secret inventory docs for Cloudflare DNS and immutable assets.

## Verification

- `bash -n scripts/deploy-sst.sh`
- Ruby syntax check for `config/application.rb`
- Parse `.github/workflows/deploy.yml`
- Run an infra TypeScript/SST syntax check if local provider installation permits it
- Review `git diff` to ensure no secrets or broad unrelated changes were introduced
