## Plan 01 - Spec Evidence

- `./run-rspec.sh` is not usable from this repo checkout because it resolves `ROOT_DIR` to the parent directory and then fails to find a `docker compose` config there.
- Used direct test command instead:
  `docker compose run -e RAILS_ENV=test web bundle exec rspec spec/requests/admin_operations_routes_spec.rb spec/controllers/admin/cases_controller_spec.rb --format progress --color`
- Result: `11 examples, 0 failures`.
- Request-spec coverage now captures:
  - admin root guest/non-editor denial and editor success
  - representative editor access for `admin/readers`, `admin/deployments`, and substitute `admin/reading_lists`
  - representative editor success for `admin/cases/:id`, `admin/readers/:id`, `admin/deployments/:id`, `admin/reading_lists/:id`, and `admin/ahoy/events/:id`
  - `admin/ahoy/events` newest-first ordering
  - `/sidekiq` anonymous redirect to sign-in, non-editor `404` under the editor-only route constraint, and editor landing-page success
- Controller-spec coverage now captures:
  - editor success path for `POST /admin/cases/:id/copy`
  - non-editor redirect away from the copy route
- Ahoy admin fix applied during spec pass:
  - `Ahoy::EventDashboard` now renders a plain `user_name` string instead of an Administrate `belongs_to` field under the nested `admin/ahoy` namespace.
  - `Ahoy::Event#user_name` returns the associated reader name or `Anonymous`.
- Shared admin `belongs_to` view hardening applied during browser QA:
  - custom `app/views/fields/belongs_to/_index.html.erb` and `_show.html.erb` now fall back to plain labels when `display_associated_resource` or namespaced route generation fails.
  - this fixed the live `GET /admin/readers/:id` show-page `500` triggered by an associated `active_community` render path.
