# Plan 26-02: Add advisory CI validation report and GitHub commit status

<objective>
Create a GitHub Actions CI validation workflow that runs on main pushes and PR commits, normalizes unit/integration/system plus SST evidence into a terse ANSI/plain-text report artifact, detects potentially destructive infrastructure changes as advisory warnings, and posts one advisory GitHub commit status through the REST API without coupling deploy execution to CI result.
</objective>

<decision_coverage>
- D-05: Run CI automatically on every commit pushed to `main`.
- D-06: Run CI automatically on every commit pushed to a pull request branch regardless of PR state.
- D-07: Keep deploy `workflow_dispatch` / operator-driven; CI status is advisory only and must not deploy, auto-promote, or mutate production.
- D-08: Keep deploy eligibility independent from CI result so operators can use judgment.
- D-09: Publish one advisory GitHub commit status per commit with `target_url` pointing to the report artifact.
- D-10: Use the GitHub REST API and a stable `gala/ci-validation` status context.
- D-11: Avoid separate suite statuses unless a later phase proves the single advisory status insufficient.
- D-12: Store the report as a GitHub Actions artifact, not a committed file or PR-comment-only result.
- D-13: Normalize test results into `unit`, `integration`, and `system`.
- D-14: Classify Jest/helper/reducer/component-unit and focused Ruby model/service checks as `unit`.
- D-15: Classify RSpec request/controller/job/service flows that exercise routing, persistence, cache, or background boundaries as `integration`.
- D-16: Classify Playwright/Capybara/browser/visual and route-facing smoke checks as `system`.
- D-17: Render missing suites as `not run` with a reason.
- D-18: Include `sst refresh` and `sst diff` evidence when safe credentials and stage context are available.
- D-19: Treat `sst refresh` and `sst diff` as report inputs only; do not deploy or mutate Heroku, production DNS, or retained shared resources.
- D-20: Detect potentially destructive infrastructure keywords and summarize advisory warnings with confidence.
- D-21: Keep destructive keyword findings advisory and non-blocking for deploy eligibility.
- D-22: Use high-signal destructive terms for delete, destroy, replace, removal, drop, recreate, force, detach, policy removal, public access, bucket deletion, DNS alias changes, database replacement, cache replacement, secret removal, and IAM broadening.
- D-23: Keep the report terse and high signal, with summarized evidence and links to details.
- D-24: Include a single-line commit/change summary truncated to 80 characters.
- D-25: Include contributors, commit count, changeset summary, test matrix, infra diff summary, release gates, destructive warnings, and confidence score.
- D-26: Use an ANSI/plain-text matrix format.
- D-27: Link failing tests to relevant artifacts, test files, or line-oriented failure excerpts when possible.
</decision_coverage>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| T-26-05: CI workflow accidentally deploys or mutates production. | high | Workflow must not contain `sst deploy`, Heroku mutation commands, production DNS mutation commands, or destructive S3 sync/delete commands. |
| T-26-06: Report artifact leaks secrets or raw environment values. | high | Report generator redacts secret-like keys and does not upload hidden files or raw environment dumps. |
| T-26-07: Status publication uses too many contexts and creates CODEOWNER noise. | medium | Publish one stable advisory context, `gala/ci-validation`, with a linked artifact. |
| T-26-08: Destructive keyword warning is misinterpreted as automatic deploy block. | medium | Report and status descriptions must label destructive findings as advisory; deploy workflows must not depend on the status. |
| T-26-09: Untrusted PR code gets elevated secrets through `pull_request_target`. | high | Use normal `pull_request`, not `pull_request_target`, and degrade status posting if token permissions are unavailable. |
</threat_model>
