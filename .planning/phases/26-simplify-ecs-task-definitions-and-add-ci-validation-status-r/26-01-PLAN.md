# Plan 26-01: Simplify SST/ECS task definitions behind auditable helpers

<objective>
Reduce duplicated SST/ECS task-definition configuration in `infra/sst.config.ts` by introducing shared helpers for Rails runtime environment, secrets, image selection, IAM/logging defaults, and task/service options while preserving explicit task-specific commands and the existing Heroku-safety boundaries.
</objective>

<decision_coverage>
- D-01: Use a shared factory/helper for SST ECS task definitions across web, worker, migration, seed/import, index refresh, maintenance, and scheduled report tasks.
- D-02: Remove repeated environment, secret, image, IAM, logging, and resource defaults while keeping task-specific commands explicit.
- D-03: Keep production task behavior auditable; avoid an abstraction layer that hides task behavior.
- D-04: Preserve runtime boundaries for SST-managed AWS database/cache, excluded Heroku database/cache, shared SES credentials, and retained S3 media resources.
</decision_coverage>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| T-26-01: Helper refactor accidentally reintroduces Heroku `DATABASE_URL` or `REDIS_URL` into AWS task definitions. | high | Preserve SST-generated database/cache URL flow and keep sensitive values in ECS secrets/SSM bindings, not plaintext environment. |
| T-26-02: Helper abstraction hides destructive or production-specific task commands. | medium | Keep each service/task resource name and command array explicit at the call site. |
| T-26-03: Shared helper drops a task-specific IAM permission, schedule, CPU/memory value, or load balancer behavior. | medium | Before editing, inventory existing task differences and preserve them as helper arguments or explicit overrides. |
| T-26-04: TypeScript/SST refactor changes production resources without review. | high | Validate with `cd infra && npm exec tsc -- --noEmit` and dev-stage `sst diff` evidence in Plan 26-02 before deploy. |
</threat_model>
