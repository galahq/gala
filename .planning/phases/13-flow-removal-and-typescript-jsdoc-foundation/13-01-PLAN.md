# Plan

## Goal

Remove Flow from active frontend source and tooling while introducing a conservative TypeScript/JSDoc foundation that does not change runtime bundling behavior.

## Tasks

1. Strip Flow syntax and comments from active JavaScript source.
   - Run a mechanical `flow-remove-types` pass over `app/javascript`, `config/webpack`, `config/locales/index.js`, `spec/support/jest-setup.js`, and `jest.config.js`.
   - Preserve unrelated dirty edits in the four pre-existing dirty files.
   - Confirm no `@flow`, `@noflow`, `$FlowFixMe`, or `FlowFixMe` markers remain in active frontend/config/test JavaScript.

2. Remove Flow tooling.
   - Remove Flow dependencies from `package.json`.
   - Remove `@babel/preset-flow` from `.babelrc.js`.
   - Remove flowtype extends/plugin/rules from `.eslintrc.json`.
   - Delete `.flowconfig`.
   - Regenerate `pnpm-lock.yaml` with pnpm.

3. Add TypeScript/JSDoc foundation.
   - Add `typescript` as a dev dependency.
   - Add root `tsconfig.json` with `allowJs`, `checkJs: false`, `noEmit`, JSX support, bundler-compatible module resolution, and explicit excludes.
   - Document that JSDoc is allowed for low-risk JavaScript typing and broad suppressions require migration reasons.

4. Verify.
   - Run `pnpm install --frozen-lockfile`.
   - Run `pnpm test -- --runInBand`.
   - Run Docker asset precompile through Shakapacker/Webpack.
   - Run static Flow-removal scans.

5. Close the phase.
   - Write `13-01-SUMMARY.md`.
   - Write `13-VERIFICATION.md`.
   - Mark TYPE requirements and Phase 13 complete in planning artifacts.
   - Commit the phase.

## Acceptance Criteria

- Active frontend source builds and tests without Flow parsing.
- Flow dependencies and config are removed.
- TypeScript is available as the future typing path.
- JSDoc is explicitly accepted for incremental JavaScript typing.
- No new broad ignore comments are introduced.
