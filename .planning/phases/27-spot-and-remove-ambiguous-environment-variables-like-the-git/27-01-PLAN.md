<objective>
Remove ambiguous blank-like plaintext environment variables from SST-generated ECS task definitions while preserving explicit Rails task behavior, existing SSM/ECS secret bindings, and the no-deploy AWS safety boundary.
</objective>

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
| --- | --- | --- |
| Secret exposure through validation output | high | Verification commands must name env vars only and must not print environment values or secret values. |
| Accidental production mutation | high | Use only source edits and read-only `sst diff --stage dev`; do not run `sst deploy`, Heroku mutation commands, or DNS mutation commands. |
| Runtime config regression from over-filtering | medium | Filter only plaintext env entries whose values are `null`, `undefined`, `""`, or whitespace-only; leave SSM/ECS secret bindings unchanged. |
| Loss of task auditability | medium | Keep web, worker, migration, seed, refresh, and scheduled task commands explicit at their existing call sites. |
</threat_model>

<must_haves>
- **MH-01:** `infra/sst.config.ts` omits blank-like plaintext runtime environment values before ECS task definitions consume them.
- **MH-02:** Blank-like means `""`, whitespace-only strings, `null`, and `undefined`.
- **MH-03:** Cleanup applies broadly to task-definition plaintext environment entries, not only `GIT_*` keys.
- **MH-04:** No blank-env allowlist is introduced.
- **MH-05:** Existing runtime secrets remain in the SSM/ECS secret path and are not moved into plaintext env.
- **MH-06:** Task-specific commands remain explicit and unchanged.
- **MH-07:** Verification includes static source assertions plus read-only `sst diff --stage dev` evidence.
- **MH-08:** No deploy, Heroku mutation, or production DNS mutation is performed.
</must_haves>

<task id="27-01-02" type="implementation">
  <title>Add central blank-environment filtering</title>
  <read_first>
  - `infra/sst.config.ts`
  </read_first>
  <action>
  Add a small helper named `compactRuntimeEnvironment` in `infra/sst.config.ts`. It must accept plaintext runtime environment entries with values typed as `string | null | undefined`, and it must return only entries where the value is not `null`, not `undefined`, and `value.trim().length > 0`. Apply this helper to the shared Rails plaintext runtime environment before it is used by `railsTaskDefaults`, `railsServiceDefaults`, or any ECS service/task definition. Do not apply this helper to `railsRuntimeSecrets` or any SSM/ECS secret binding.
  </action>
  <verify>
  Run `rg -n "compactRuntimeEnvironment|trim\(\)|railsRuntimeEnvironment" infra/sst.config.ts`.
  </verify>
  <acceptance_criteria>
  - `infra/sst.config.ts` contains `compactRuntimeEnvironment`.
  - `compactRuntimeEnvironment` rejects `null`, `undefined`, `""`, and whitespace-only strings with a trim-based predicate.
  - `railsRuntimeEnvironment` or the equivalent shared plaintext environment boundary is constructed through `compactRuntimeEnvironment`.
  - `railsRuntimeSecrets` remains separate and is not stringified, filtered, or moved into plaintext environment configuration.
  - No blank-env allowlist is introduced.
  </acceptance_criteria>
</task>
