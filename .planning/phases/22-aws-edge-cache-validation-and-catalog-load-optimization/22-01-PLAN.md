# Plan 22-01: Validate App Edge Cache And Reduce Anonymous Catalog Load Cost

## Objective

Make the AWS root catalog path perform on par with or faster than Heroku for repeat anonymous loads by validating the Phase 21 app CloudFront distribution first, then applying only narrow, reversible changes to anonymous catalog cache TTLs and anonymous catalog frontend fetch behavior.

## Non-Negotiables

- Do not change Heroku production, production DNS, SES, or the retained `msc-gala` ActiveStorage media bucket.
- Do not route `msc-gala` ActiveStorage directly through CloudFront in this phase.
- Keep CloudFront default app behavior uncached/pass-through.
- Cache only explicitly approved anonymous public GET paths.
- Preserve signed-in and session-specific catalog behavior.

## Execution Tasks

1. **Deploy or confirm the Phase 21 app CloudFront distribution**
   - Check live CloudFront distributions with `AWS_PROFILE=gala AWS_REGION=us-west-2`.
   - If `GalaAppDistribution` is absent, deploy the current branch through the existing SST GitHub Action path, not by changing DNS or Heroku.
   - Capture `appCdnUrl`, distribution ID, and current ALB URL before measuring.

2. **Measure the live app-edge path before adding more changes**
   - Request `/cases.json`, `/cases/features.json`, `/catalog/libraries.json`, `/tags.json`, and `/` through `appCdnUrl`.
   - Repeat anonymous requests and record `x-cache`, `age`, `cache-control`, `x-runtime`, total time, and response size.
   - Compare the second app-edge anonymous `/cases.json` request against the current Heroku `/cases.json` timing.
   - Verify the direct ALB path still works for rollback comparison.

3. **Increase anonymous public catalog JSON TTLs only if validation is safe**
   - If app-edge cache hits are correct but TTL is too short, increase anonymous public catalog JSON cache TTLs from 60 seconds to a conservative 300 seconds.
   - Keep query-specific or signed-in responses private or uncached.
   - Keep CloudFront cookie forwarding for these paths unless a separate public-only endpoint is introduced.
   - Keep the change limited to `PublicCatalogCache` and `infra/sst.config.ts`.

4. **Optionally add guarded anonymous root HTML caching**
   - Add root `/` CloudFront cache behavior only if the Rails response can be made public exclusively for anonymous, no-cookie, no-query, no-selection-session requests.
   - Include `Accept-Language` in the cache key because root locale can vary by request headers.
   - Do not cache root responses for signed-in users, session cookies, content item selection sessions, or query parameters.
   - Skip this task if the guard is not obviously safe in code.

5. **Remove anonymous private fetch noise from the catalog frontend**
   - Use the already-rendered `window.reader` value as the initial reader state.
   - For anonymous visitors, skip `/profile.json`, `/enrollments.json`, `/saved_reading_lists.json`, and `/managerships.json`.
   - Keep signed-in behavior intact by still loading reader-specific data when `window.reader` is present.
   - Remove anonymous-only preload tags for private endpoints in `app/views/catalog/home.html.haml`.

6. **Document the SST Router decision**
   - Record that SST Router is viable for future managed static asset plus ALB routing.
   - Record that `routeBucket` is not used for `msc-gala` in this phase because ActiveStorage media needs a separate signed-media and bucket-policy design.

## Verification

- `ruby -c` for any touched Ruby files.
- Targeted request specs for anonymous catalog cache headers and signed-in/private behavior.
- Targeted frontend test or full `pnpm test -- --runInBand` if no focused catalog test exists for touched JavaScript.
- `AWS_PROFILE=gala AWS_REGION=us-west-2 npx sst diff --stage production`.
- Post-deploy read-only smoke checks through `appCdnUrl`:
  - second anonymous `/cases.json` request is a CloudFront hit or shows expected edge cache behavior,
  - signed-in or cookie-bearing catalog requests do not receive shared public content,
  - root catalog load no longer makes anonymous private endpoint requests,
  - direct ALB `/up` and `/` still return `200 OK`.

## Acceptance Criteria

- App CloudFront is live and validated before broader CloudFront changes are accepted.
- Repeat anonymous `/cases.json` through app CloudFront is faster than Heroku or clearly cache-hit bounded by edge delivery rather than Rails serialization.
- Anonymous catalog JSON caching remains limited to public catalog data.
- Anonymous root catalog load avoids avoidable 401 private endpoint requests.
- No SST diff attempts to alter Heroku, DNS, SES, or `msc-gala`.
- The rollout remains reversible by using the direct ALB URL or prior ECS/SST deployment state.
