# Phase 21 Plan: AWS Performance and Edge Cache Optimization

## Goal

Reduce AWS catalog load latency while keeping the rollout reversible and isolated from Heroku production, SES, production DNS, and the retained `msc-gala` media bucket.

## Work Items

1. Add immutable browser cache headers for fingerprinted static assets.
   - Add `Cache-Control: public,max-age=31536000,immutable` to SST static CloudFront viewer responses.
   - Add the same metadata to `scripts/deploy-sst.sh` S3 sync uploads for `/assets/*` and `/packs/*`.

2. Add a separate app CloudFront distribution in SST.
   - Origin points at the SST web ALB.
   - Default behavior allows all app methods but uses `defaultTtl: 0`, `maxTtl: 0`, forwards all headers/cookies/query strings, and therefore does not cache dynamic app traffic.
   - Ordered behaviors cache only known public catalog JSON paths for a short TTL: `/cases.json`, `/cases/features.json`, `/catalog/languages.json`, `/catalog/libraries.json`, `/tags.json`.

3. Add app-side public cache headers for anonymous catalog JSON.
   - Use a shared controller concern so only anonymous JSON with no query parameters receives public `Cache-Control`.
   - Keep signed-in, personalized, or query-specific responses private/uncached.
   - Cache rendered JSON briefly in Rails to reduce repeated serializer work.

4. Increase AWS runtime headroom.
   - Production `GalaWeb`: 1 vCPU, 2 GB memory.
   - Production `GalaWorker`: 0.5 vCPU.
   - Production Puma: 5 threads and 2 workers by default, with `preload_app!` and ActiveRecord reconnect.

5. Validate without mutation.
   - Run Ruby syntax checks for touched controller/runtime files.
   - Run the targeted catalog request spec if the local bundle is available.
   - Run `AWS_PROFILE=gala AWS_REGION=us-west-2 npx sst diff --stage production`.

## Acceptance

- SST diff previews the new CloudFront distribution and task sizing without touching Heroku, SES, DNS, or the media bucket.
- Static asset responses can carry immutable cache headers.
- Anonymous catalog JSON can be cached at CloudFront and Rails for short windows.
- Signed-in catalog JSON remains private.
- The project remains deployable through the existing SST GitHub Action path.
