<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry to local install | Package metadata and tarball resolution enter the local dependency graph through pnpm. |
| lockfile to build/test | `pnpm-lock.yaml` controls code loaded by Jest, Webpack, and Shakapacker. |
| dirty worktree to migration | Pre-existing manifest/lockfile diffs can be accidentally reverted or misattributed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | `package.json` package-manager metadata | mitigate | Recheck `npm view pnpm ... --json`, pin exact `packageManager`, and assert `engines.pnpm` matches the pin. |
| T-11-02 | Tampering | `pnpm-lock.yaml` | mitigate | Generate via `pnpm import`; verify with `pnpm install --frozen-lockfile`; do not hand-edit lockfile. |
| T-11-03 | Repudiation | pre-existing `package.json` and `yarn.lock` diffs | mitigate | Classify and record current diffs before mutation; leave unrelated user edits untouched. |
| T-11-04 | Denial of Service | pnpm default dependency layout | mitigate | Run install/build/test gates; add direct deps or `.npmrc` fallback only with concrete failing evidence. |
</threat_model>
