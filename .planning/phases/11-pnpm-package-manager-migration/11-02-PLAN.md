<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI checkout to Semaphore install | CI reads committed package metadata and lockfile to populate `node_modules`. |
| Docker build context to image | Docker copies dependency manifests and installs packages in the container layer. |
| documentation to developer shell | README/docs/bin instructions cause developers to run package-manager commands locally or in Docker. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05 | Tampering | `.semaphore/semaphore.yml` cache key | mitigate | Key root JavaScript cache to `pnpm-lock.yaml` and install with `pnpm install --frozen-lockfile`. |
| T-11-06 | Denial of Service | `Dockerfile` package install layer | mitigate | Replace global Yarn install with pinned pnpm activation and verify Dockerfile has no `yarn.lock` copy path. |
| T-11-07 | Spoofing | developer docs/package-manager invocation | mitigate | Use Corepack/pnpm commands tied to `package.json` `packageManager`; remove `bin/yarn` assumptions. |
| T-11-08 | Tampering | `infra/` npm workflow boundary | mitigate | Explicitly leave `infra/package-lock.json` and GitHub npm workflow unchanged unless root docs need clarification. |
</threat_model>
