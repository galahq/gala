# Plan 25-01: Operator Surface Audit and Guardrail Contract

<objective>
Create the concise operator safety contract that the implementation plans must follow. Audit the existing Docker, SST task, GitHub Actions, deploy script, CODEOWNERS, and runbook surfaces, then record the exact guardrail gaps before workflow files are changed.
</objective>

<threat_model>
- Planning workflow changes without a current-state audit can accidentally remove existing safety checks in `scripts/deploy-sst.sh`, `.github/workflows/deploy.yml`, or `.github/workflows/preview.yml`.
- A vague operator contract can allow arbitrary shell execution, direct runner access to production DB/Redis, broad token permissions, or hidden production side effects.
- Documentation can drift from implementation if it is written before the workflow inventory and side-effect matrix are explicit.
- Audit artifacts must not quote secret values from local env files, GitHub secrets, Rails credentials, Heroku config, or encrypted credentials.
</threat_model>

<must_haves>
- **D-01:** Hybrid workflow shape: separate deploy/promote/rollback, shared maintenance.
- **D-02:** Maintenance covers migrations, one-off scripts, Rails cache clearing, and CloudFront invalidation.
- **D-03:** PR merge-to-base is documented as a protected branch process, not a dispatch mutation.
- **D-04:** Operator actions must be manual `workflow_dispatch` jobs.
- **D-08:** Immediate rollback prefers ECS task-definition rollback.
- **D-11:** Production Rails operations must run as ECS one-off tasks.
- **D-17:** Operator docs live under `docs/ops/workflows/*.md`.
</must_haves>
