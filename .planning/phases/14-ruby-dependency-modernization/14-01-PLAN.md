# Plan

## Goal

Apply compatible runtime gem updates without crossing major runtime/auth/monitoring boundaries.

## Tasks

1. Update Gemfile constraints.
   - Relax `pg` from `~> 1.5.4` to `~> 1.6`.
   - Keep `puma` on `~> 7.1`, `sidekiq` on `~> 7.0`, `redis` on `~> 5.0`, and Sentry gems on `~> 5.24`.

2. Run targeted Bundler update in Docker.
   - Update `pg`, `puma`, `sidekiq`, `redis`, `rack-attack`, and related support gems.
   - Do not allow Puma 8, Sidekiq 8, Devise 5, Sentry 6, RSpec Rails 8, or Administrate 1 into this batch.

3. Verify runtime gates.
   - `docker compose exec web bundle check`
   - `docker compose exec web bundle exec rails runner 'puts Rails.version'`
   - `docker compose exec web bundle exec rspec`
   - `docker compose exec web sh -lc 'SECRET_KEY_BASE=build-placeholder DATABASE_URL=postgresql://placeholder/placeholder bundle exec rails assets:precompile'`

4. Document major holdbacks and runtime results.

## Acceptance Criteria

- Runtime gem updates resolve and install in Docker.
- Rails boots under updated gems.
- RSpec passes or any failure is clearly unrelated and documented.
- Major holdbacks are documented.
