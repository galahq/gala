# Phase 7 Plan 01: Deployment and Integration Route Stabilization

## Goal

Stabilize deployment, Canvas/LTI, content-item, and integration route behavior while preserving the upgraded BlueprintJS styling compatibility layer.

## Tasks

1. Add static `bp4` counterparts to deployment-specific hand-written Blueprint classes in server-rendered templates, decorators, and deployment React components.
2. Add request specs for deployment index/show/new/create/edit/update, submissions access, LTI config, content-item validation, and Canvas deployment session boundaries.
3. Re-run existing SPARQL route coverage as part of the Phase 7 integration gate.
4. Browser-smoke representative deployment routes on `localhost:3000` as practical, checking console and network errors.
5. Record QA evidence and commit before moving to Phase 8.

## Risk Notes

- Do not weaken LTI request validation or CSRF-skip boundaries.
- Do not change deployment quiz customization payload semantics.
- Do not broaden deployment authorization beyond existing `DeploymentPolicy` behavior.
