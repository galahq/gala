# Plan 28-02: Prove ARM64 image build and read-only dev rendering

<objective>
Prove or block ARM64 without live deployment by building the base/app images,
running a container smoke check, capturing pre-ARM rollback references, and
rendering dev SST task definitions in read-only mode.
</objective>

<tasks>

<task id="28-02-01" type="auto">
  <name>Build and smoke ARM64 production images</name>
  <files>.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md</files>
  <read_first>
  - `Dockerfile.production-base`
  - `Dockerfile.production`
  - `Gemfile.lock`
  - `package.json`
  - `pnpm-lock.yaml`
  - `.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-RESEARCH.md`
  </read_first>
  <action>
  Build `Dockerfile.production-base` for `linux/arm64` with tag `gala-production-base:phase28-arm64`. Then build `Dockerfile.production` for `linux/arm64` with `GALA_PRODUCTION_BASE_IMAGE=gala-production-base:phase28-arm64` and tag `gala-production:phase28-arm64`. Inspect the app image architecture and run a safe runtime smoke such as `ruby -v` in the image. Record commands, exit status, image OS/architecture, and native dependency observations in `28-DECISION.md` under `## ARM64 Image Evidence`. If the local builder cannot load ARM64 images, record the exact blocker and a dev-safe ECR fallback tag; do not push `latest`.
  </action>
  <verify>
  `docker buildx build --platform linux/arm64 -f Dockerfile.production-base -t gala-production-base:phase28-arm64 --load .`
  `docker buildx build --platform linux/arm64 -f Dockerfile.production --build-arg GALA_PRODUCTION_BASE_IMAGE=gala-production-base:phase28-arm64 -t gala-production:phase28-arm64 --load .`
  `docker image inspect gala-production:phase28-arm64 --format '{{.Os}}/{{.Architecture}}'`
  `docker run --rm --platform linux/arm64 gala-production:phase28-arm64 ruby -v`
  </verify>
  <acceptance_criteria>
  - Successful image inspection returns `linux/arm64`, or `28-DECISION.md` records the exact blocker.
  - ARM64 runtime smoke exits 0, or `28-DECISION.md` records the exact blocker.
  - `28-DECISION.md` notes `Gemfile.lock` ARM Linux platform coverage and any native dependency issue.
  - No production-facing `latest` tag is pushed.
  </acceptance_criteria>
  <done>`28-DECISION.md` contains ARM64 image build, inspection, and runtime smoke evidence or exact blockers.</done>
</task>

<task id="28-02-02" type="auto">
  <name>Capture pre-ARM dev rollback references</name>
  <files>.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md</files>
  <read_first>
  - `.github/workflows/rollback.yml`
  - `docs/ops/workflows/rollback.md`
  - `scripts/ops/operator-common.sh`
  - `.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-RESEARCH.md`
  </read_first>
  <action>
  Before any ARM64 dev deploy, use read-only AWS ECS commands to capture the current dev web and worker service task definition ARNs, their `runtimePlatform.cpuArchitecture`, and current image identifiers. Record them in `28-DECISION.md` under `## Pre-ARM Dev Rollback Capture`. If AWS read-only access is unavailable, record the blocker and mark ARM64 production default as blocked until the capture is complete.
  </action>
  <verify>
  `aws ecs describe-services --cluster <dev-cluster> --services <dev-web-service> <dev-worker-service> --region us-west-2 --profile gala`
  `aws ecs describe-task-definition --task-definition <captured-task-definition-arn> --region us-west-2 --profile gala`
  </verify>
  <acceptance_criteria>
  - `28-DECISION.md` contains `## Pre-ARM Dev Rollback Capture`.
  - Web and worker pre-ARM task definition ARNs are captured before any ARM rollout, or an explicit blocker is recorded.
  - Evidence includes current `cpuArchitecture` and image identifier without secret values.
  - Missing pre-ARM capture blocks any production ARM64 default flip.
  </acceptance_criteria>
  <done>Rollback source task definitions are captured before live ARM validation can begin, or the blocker is explicit.</done>
</task>

<task id="28-02-03" type="auto">
  <name>Run read-only dev SST ARM64 diff</name>
  <files>.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md</files>
  <read_first>
  - `infra/sst.config.ts`
  - `scripts/deploy-sst.sh`
  - `.github/workflows/preview.yml`
  - `.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-VALIDATION.md`
  </read_first>
  <action>
  Run read-only `sst diff --stage dev --json` with `GALA_CONTAINER_ARCHITECTURE=arm64`, `AWS_PROFILE=gala`, `AWS_REGION=us-west-2`, `SST_STAGE=dev`, and explicit ARM64-compatible base or app image input. Save output to `/tmp/phase28-arm64-sst-diff.json`. Record in `28-DECISION.md` under `## Dev ARM64 Render Evidence` whether web, worker, migration, seed/one-off, refresh, and scheduled task definitions render `runtimePlatform.cpuArchitecture=ARM64`. Summarize destructive-looking diff output as a blocker before any live deploy.
  </action>
  <verify>
  `cd infra && AWS_PROFILE=gala AWS_REGION=us-west-2 SST_STAGE=dev GALA_CONTAINER_ARCHITECTURE=arm64 GALA_PRODUCTION_BASE_IMAGE=353760060567.dkr.ecr.us-west-2.amazonaws.com/gala-production-base:ruby4.0.3-bookworm-pg17-runtime-v1-arm64 npx sst diff --stage dev --json > /tmp/phase28-arm64-sst-diff.json`
  `test -s /tmp/phase28-arm64-sst-diff.json`
  </verify>
  <acceptance_criteria>
  - `/tmp/phase28-arm64-sst-diff.json` exists and is non-empty, or `28-DECISION.md` records the exact AWS/SST blocker.
  - `28-DECISION.md` records rendered/read-only evidence for web, worker, migration, and one-off/task architectures.
  - No `sst deploy` is run.
  - Any risky diff output is called out before Plan 28-03.
  </acceptance_criteria>
  <done>Read-only dev SST evidence shows ARM64 task rendering or blocks live validation with exact evidence.</done>
</task>
