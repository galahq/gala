# Plan 28-03: Validate ARM64 in dev ECS and prove rollback

<objective>
Run the operator-gated live dev validation that decides whether ARM64 is
production-capable: web, worker, migration, one-off task, then web/worker
task-definition rollback.
</objective>

<tasks>

<task id="28-03-01" type="auto">
  <name>Deploy ARM64 candidate to dev and verify runtime surfaces</name>
  <files>.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md</files>
  <read_first>
  - `.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md`
  - `scripts/deploy-sst.sh`
  - `.github/workflows/preview.yml`
  - `scripts/ops/operator-common.sh`
  - `docs/ops/workflows/maintenance.md`
  </read_first>
  <action>
  With operator approval and dev AWS credentials, deploy the ARM64 candidate to `SST_STAGE=dev` using `GALA_CONTAINER_ARCHITECTURE=arm64` and the ARM64 base/app image proven in Plan 28-02. Verify web `/up`, worker Sidekiq boot/log evidence, migration safe command `bundle exec rails db:version`, and one-off safe command `bundle exec rails runner 'puts :ok'` through the established ECS task/maintenance path. Record task definition ARNs, image URI/digest, `runtimePlatform.cpuArchitecture`, health status, command exit statuses, and log links in `28-DECISION.md` under `## Dev ARM64 Runtime Evidence`. If approval or credentials are unavailable, record the blocker and mark ARM64 production default as blocked; do not print secret values.
  </action>
  <verify>
  Operator-selected dev deploy command exits 0, then read-only AWS ECS/CloudWatch checks confirm web `/up`, worker logs, migration safe command exit status, and one-off safe command exit status.
  </verify>
  <acceptance_criteria>
  - `28-DECISION.md` contains `## Dev ARM64 Runtime Evidence`.
  - Web evidence includes `/up` returning HTTP 200-399.
  - Worker evidence includes ARM64 task definition and Sidekiq boot/log evidence.
  - Migration and one-off evidence use safe non-mutating commands.
  - Missing proof marks ARM64 production default as blocked.
  </acceptance_criteria>
  <done>Dev ARM64 runtime proof covers web, worker, migration, and one-off paths, or records a production-blocking reason.</done>
</task>

<task id="28-03-02" type="auto">
  <name>Run dev web and worker task-definition rollback drill</name>
  <files>.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md</files>
  <read_first>
  - `.planning/phases/28-verify-arm-ecs-fargate-runtime-architecture-and-resolve-thru/28-DECISION.md`
  - `.github/workflows/rollback.yml`
  - `docs/ops/workflows/rollback.md`
  - `scripts/ops/operator-common.sh`
  </read_first>
  <action>
  Using the pre-ARM web and worker task definition ARNs captured in Plan 28-02, run the existing rollback task-definition path for `stage=dev`, `lane=task_definition`, `service=both`, `web_task_definition=<captured-web-arn>`, `worker_task_definition=<captured-worker-arn>`, and `dry_run=true` first. With operator approval, run the live dev rollback. Verify web `/up`, worker logs, ECS service stability, and restored task definition ARNs after rollback. Record dry-run summary, live rollback summary, post-rollback task definitions, and verification in `28-DECISION.md` under `## Dev Rollback Evidence`. If rollback proof is incomplete, mark ARM64 production default as blocked.
  </action>
  <verify>
  Rollback dry-run exits 0; live dev rollback exits 0 with operator approval; read-only `aws ecs describe-services`, `aws ecs describe-task-definition`, web `/up`, and worker log checks confirm both services are restored and stable.
  </verify>
  <acceptance_criteria>
  - `28-DECISION.md` contains `## Dev Rollback Evidence`.
  - Rollback dry run is recorded before live dev rollback.
  - Live dev rollback covers both web and worker.
  - Post-rollback web `/up` returns HTTP 200-399 and worker evidence shows stable boot/running state.
  - Incomplete rollback proof blocks production ARM64 default.
  </acceptance_criteria>
  <done>Web and worker task-definition rollback has live dev evidence or explicitly blocks ARM64 production default.</done>
</task>
