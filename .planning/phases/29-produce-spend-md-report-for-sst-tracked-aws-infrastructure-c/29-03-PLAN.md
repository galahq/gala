# Plan 29-03: Validate SPEND.md and harden decision quality

<objective>
Validate the spend report against Phase 29 success criteria, remove unsafe or
unsupported claims, and make the final Heroku migration decision framing clear.
</objective>

<threat_model>
- T-29-07: Report contains secret-looking values or connection strings.
  Mitigation: run static secret-pattern scan and remove any sensitive output.
- T-29-08: Report hides infrastructure drift. Mitigation: add explicit
  source-vs-live drift and unknowns table.
- T-29-09: Report gives a migration recommendation without decision thresholds.
  Mitigation: require stay/hybrid/migrate thresholds and missing-evidence list.
</threat_model>

<tasks>

<task id="29-03-01" type="auto">
  <name>Run static safety and completeness validation</name>
  <files>SPEND.md, .planning/phases/29-produce-spend-md-report-for-sst-tracked-aws-infrastructure-c/29-EVIDENCE.md</files>
  <read_first>
  - `SPEND.md`
  - `.planning/phases/29-produce-spend-md-report-for-sst-tracked-aws-infrastructure-c/29-VALIDATION.md`
  </read_first>
  <action>
  Run the quick and full validation commands from `29-VALIDATION.md`. Fix missing required sections, remove secret-looking values, and ensure every material AWS service in the inventory has a cost driver or explicit "not material / unknown" note.

  <verify>
  `rg -n "EXECUTIVE SUMMARY|SCOPE|INVENTORY|CAPEX|OPEX|GROWTH MODEL|CUT COST|HEROKU DECISION|EVIDENCE|UNKNOWN" SPEND.md`
  `ruby -e 'p=File.read("SPEND.md"); %w[EXECUTIVE\\ SUMMARY SCOPE INVENTORY CAPEX OPEX GROWTH\\ MODEL CUT\\ COST HEROKU\\ DECISION EVIDENCE UNKNOWN].each { |s| abort("missing #{s}") unless p.match?(/#{s}/i) }; abort("secret-like") if p.match?(/postgres:\\/\\/|rediss?:\\/\\/|SECRET_KEY|PASSWORD=|TOKEN=/)'`
  </verify>
  <acceptance_criteria>
  - Required sections are present.
  - Secret-pattern scan passes.
  - Every resource category has a cost treatment.
  </acceptance_criteria>
  <done>Report passes static completeness and safety checks.</done>
</task>

<task id="29-03-02" type="manual">
  <name>Reconcile source live drift and unknowns</name>
  <files>SPEND.md, .planning/phases/29-produce-spend-md-report-for-sst-tracked-aws-infrastructure-c/29-EVIDENCE.md</files>
  <read_first>
  - `SPEND.md`
  - `.planning/phases/29-produce-spend-md-report-for-sst-tracked-aws-infrastructure-c/29-EVIDENCE.md`
  - `infra/sst.config.ts`
  </read_first>
  <action>
  Compare `infra/sst.config.ts` against the latest read-only AWS inventory and add a drift/unknowns table. At minimum, check production DB allocated storage versus source intent, router CloudFront price class versus source transform, old `learngala.com` distributions versus SST `learngala.dev` scope, retained media bucket ownership, image count/retention, and log retention visibility.
  </action>
  <verify>
  `rg -n "Drift|Unknown|source|live|allocated storage|PriceClass|learngala.com|learngala.dev|msc-gala|ECR|log retention" SPEND.md .planning/phases/29-produce-spend-md-report-for-sst-tracked-aws-infrastructure-c/29-EVIDENCE.md`
  </verify>
  <acceptance_criteria>
  - Tracked-vs-live drift is listed separately from cost estimates.
  - Unknowns name exact evidence needed to resolve them.
  - Old/shared account resources are not silently counted as SST migration cost unless intentionally scoped.
  </acceptance_criteria>
  <done>Drift and unknowns are explicit.</done>
</task>
