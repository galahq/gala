# Phase 04 Plan 01: Core Case Shell Route Stabilization

<objective>
Stabilize the Phase 4 core case shell route group by deriving the route checklist from `config/routes.rb`, selecting existing local case data, browser-QAing the full core route sample on `localhost:3000`, applying only verified narrow fixes, running targeted tests, and recording QA evidence before commit.
</objective>

<must_haves>
## Truths

- D-01: Use a full core route sample for Phase 4 rather than a minimal smoke pass.
- D-02: Cover each scoped route family: case index JSON, case show shell, edit redirect, settings, archive, translations, copy, delete confirmation, and React Router suffix routes.
- D-03: Use existing local data first, preferring a published case plus an editor-accessible case when available.
- D-04: Document substitutions or skipped route families instead of broadening into seed-data work.
- D-05: Include editor-authenticated browser coverage for routes and controls that require it when existing credentials/session setup is available.
- D-06: Restricted routes are not fully covered by unauthenticated redirect behavior alone when editor behavior is central to the shell; request/controller specs may supplement impractical browser auth setup.
- D-07: Sample `/cases/:slug`, a content-position route such as `/cases/:slug/1`, and `/cases/:slug/conversation` when local data and auth allow.
- D-08: Preserve `.pt-*` classes, add `.bp4-*` companions only for verified route surfaces that need them, and defer cleanup to Phase 9.
- D-09: Inspect console and network failures before marking the route group complete.
- D-10: Treat browser-container HMR `Invalid Host/Origin header` as tooling noise unless reproduced at normal `localhost:3000`.
- D-11: Commit only after the Phase 4 route group passes QA or has documented, non-blocking exceptions.

## UI Contract

- Preserve the existing Gala / BlueprintJS-era appearance. Do not redesign the case shell.
- Do not add a new component library, icon system, layout framework, or global visual palette.
- Do not import Blueprint package CSS from route packs or duplicate Blueprint CSS.
- Text inside buttons, tags, toolbar items, menus, and form controls must not overflow or overlap.
- The QA evidence must record chosen slugs, route coverage, browser results, console/network findings, targeted tests, and substitutions.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-04-01 | medium | Editor-only case routes or controls could be treated as passing based only on public redirects, hiding authorization or edit-shell regressions. | Tasks require editor-authenticated browser coverage where available and authenticated specs where browser auth is impractical. |
| T-04-02 | medium | Route fixes could weaken authorization on unpublished/editable case surfaces. | Tasks require reading `CasesController`, existing specs, and policies before route behavior changes; acceptance requires targeted controller/feature specs. |
| T-04-03 | low | Broad Blueprint compatibility changes could regress earlier route groups. | Tasks restrict fixes to verified Phase 4 surfaces and forbid removing `.pt-*` classes or duplicating Blueprint CSS. |
| T-04-04 | low | Local data variance could produce false confidence or impossible QA. | Tasks require recording selected slugs, substitutions, skipped route families, and supplemental automated coverage. |
</threat_model>
