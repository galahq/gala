## Plan 01 - Spec Substitutions

- `CommentThreadsController#build_comment_thread` contains a `relation.nil?` 422 branch, but `config/routes.rb` has no unscoped `POST /comment_threads` route that can reach it. The reachable nested routes are `POST /cases/:case_slug/comment_threads` and `POST /cards/:card_id/comment_threads`; request coverage uses the card route plus invalid comment content 422 coverage.
- Request-level non-GET JSON specs explicitly stub `verified_request?` so the tests cover nested controller JSON behavior rather than Rails CSRF token generation. Browser UAT still exercises real authenticated UI requests through `/readers/sign_in` and `a.oauth-icon-google`.
- `PATCH/PUT /activities/:id` and `DELETE /activities/:id` remain documented route/controller mismatches: `config/routes.rb` exposes them, but `ActivitiesController` only implements `create`. No narrow Phase 5 visual regression fix was applied because no existing UI path reached those actions during this gate.

## Plan 01 - Fixes Applied

- `CommentThreadsController#comment_thread_params` now tolerates legacy/client range keys (`start`, `length`, `block_index`) but only passes persisted `original_highlight_text` to `CommentThread`. The serializer still derives `blockIndex`, `start`, and `length` from `CommentThreadRangeCalculator`.
