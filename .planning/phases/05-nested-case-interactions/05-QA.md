## Plan 04 - Spec Substitutions

- Wikidata remote reads are stubbed in request specs. The browser gate verifies the protected edit shell, Wikidata dialog, schema selector, QID/search input, and disabled Save state without depending on live Wikidata availability or mutating local case data.
- Lock and tag writes are covered with transactional request specs instead of browser writes. The browser gate verifies edit-mode access, Keywords controls, and the live `locks.json` read path; create/delete writes are reversible in specs and avoid changing shared local QA data.
- Request-level JSON specs stub `verified_request?` so the tests cover authenticated route/controller behavior, not CSRF token generation. Protected browser UAT still relies on `/readers/sign_in` and `a.oauth-icon-google`.

## Plan 04 - Fixes Applied

- `Wikidata#canned_query` now returns `nil` for blank QIDs or unsupported schemas instead of raising on missing schema templates.
- `Wikidata#search` now returns `nil` for blank search text instead of calling `downcase` on a blank input. The existing SPARQL controller maps nil results to 404.
- Invalid lockable type behavior was already 422; the new lock request spec preserves that behavior.
