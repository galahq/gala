<objective>
Perform a narrow, evidence-driven cleanup of upgrade leftovers in shared/global Blueprint compatibility assets, then run a broad final regression sweep over representative routes from all prior route groups. Preserve route behavior and visual baseline while removing duplicate or stale compatibility constructs that are no longer needed.
</objective>

<must_haves>
## Truths

- D-01: Cleanups remain route-driven and narrow: global/asset residues are the primary target; avoid broad redesign.
- D-02: Keep `config/routes.rb` as route scope of truth for phase-9 regression sampling.
- D-03: Global-first cleanup: mechanical dead-reference pruning before optional 1:1 safe simplifications.
- D-04: Use `localhost:3000` / `host.docker.internal:3000` for QA and record console/network findings before route completion.
- D-05: The phase closes on targeted RSpec command + targeted shared Jest contract tests.
- D-06: Browser pass/fail and non-blocking exceptions are tracked explicitly in `.planning/phases/09-deslopification-and-final-regression/09-QA.md`.
- D-07: Any route in scope that lacks a direct path in `config/routes.rb` must be documented and replaced with a route-backed substitute.
</must_haves>

<threat_model>
## Threat Model

| ID | Severity | Threat | Mitigation in Plan |
|----|----------|--------|--------------------|
| T-09-01 | medium | Removal of bridge/compatibility code may silently break legacy `.pt-*` routes still rendered in views. | Sequence changes by reference verification: mechanical dead-pass first, run contract tests, then broaden only where modern equivalents are clearly present; keep cleanup evidence in `09-QA.md`. |
| T-09-02 | medium | Route checklist may drift from actual `config/routes.rb` and produce false-positive coverage. | Build route rows directly from `config/routes.rb`; record any substituted route explicitly with rationale. |
| T-09-03 | medium | Shared blueprint contract edits can have app-wide blast radius and hide regressions until late QA. | Run shared tests immediately after each cleanup cluster and broad regression sweep before marking phase complete. |
| T-09-04 | low | Pre-existing local browser noise is misclassified as phase-9 regression. | Explicitly separate route-specific breakages from known baseline noise in QA evidence. |
</threat_model>
