# External Integrations

**Analysis Date:** 2026-04-22

## APIs & External Services

**AWS Platform:**
- AWS ECS/Fargate - Production/staging web and worker hosting.
  - SDK/Client: SST 4.7.1 AWS provider in `infra/sst.config.ts`.
  - Auth: GitHub OIDC role configured in `.github/workflows/deploy.yml`; SST secrets declared in `infra/sst.config.ts`.
- AWS RDS/Postgres - Production/staging primary database.
  - SDK/Client: `sst.aws.Postgres` in `infra/sst.config.ts`; Rails uses the `pg` gem from `Gemfile.lock`.
  - Auth: `DATABASE_URL` is generated by `infra/sst.config.ts` and injected into services/tasks.
- AWS Redis-compatible cache - Production/staging Valkey 7.2 for Redis protocol use.
  - SDK/Client: `sst.aws.Redis` in `infra/sst.config.ts`; Rails uses the `redis` gem, Sidekiq, Rails cache store, and Action Cable.
  - Auth: `REDIS_URL` is generated by `infra/sst.config.ts` and injected into services/tasks.
- AWS S3 - Production media storage for Active Storage.
  - SDK/Client: `aws-sdk-s3`; Active Storage service config in `config/storage.yml`.
  - Auth: `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` for Rails storage config; ECS task role media policy is created in `infra/sst.config.ts`.
- AWS SES SMTP - Outbound production email when SMTP credentials are configured.
  - SDK/Client: Rails Action Mailer SMTP settings in `config/environments/production.rb`.
  - Auth: `SES_SMTP_USERNAME`, `SES_SMTP_PASSWORD`.
- AWS Action Mailbox ingress - Inbound email ingress is selected as `:amazon` in `config/environments/production.rb`.
  - SDK/Client: Rails Action Mailbox; routing in `app/mailboxes/application_mailbox.rb`.
  - Auth: AWS ingress configuration outside the inspected app code; reply handling is in `app/mailboxes/replies_mailbox.rb`.

**Authentication & Learning Tools:**
- LTI 1.x tool launch and content-item selection - LMS integrations such as Canvas launch users into Gala and assign cases.
  - SDK/Client: `ims-lti`, `omniauth-lti`, Devise OmniAuth setup in `config/initializers/devise.rb`, LTI request validation in `app/controllers/application_controller.rb`.
  - Auth: `LTI_KEY`, `LTI_SECRET`.
  - Endpoints: `/authentication_strategies/auth/lti/callback` in `app/controllers/authentication_strategies/omniauth_callbacks_controller.rb`; `/catalog/content_items` in `app/controllers/catalog/content_items_controller.rb`; LTI XML config in `app/controllers/authentication_strategies/config_controller.rb` and `app/views/authentication_strategies/config/lti.xml.erb`.
- Google OAuth - Reader sign-in through Google.
  - SDK/Client: `omniauth-google-oauth2` configured in `config/initializers/devise.rb`; callback handled by `app/controllers/authentication_strategies/omniauth_callbacks_controller.rb`.
  - Auth: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
- Facebook OAuth - Gem and Devise provider configuration are present, but the active `AuthenticationStrategy` model only exposes `google` and `lti`.
  - SDK/Client: `omniauth-facebook` configured in `config/initializers/devise.rb`; provider list in `app/models/authentication_strategy.rb`.
  - Auth: `FACEBOOK_CLIENT_ID`, `FACEBOOK_CLIENT_SECRET`.

**Maps & Geospatial UI:**
- Mapbox - Interactive maps for case locations and stats maps.
  - SDK/Client: `react-map-gl` and transitive `mapbox-gl`; clients are `app/javascript/map_view/index.jsx`, `app/javascript/stats/map/MapView.jsx`, and `app/javascript/stats/map/config.js`.
  - Auth: `MAPBOX_ACCESS_TOKEN` or `MapboxAccessToken`, injected by `app/views/layouts/application.html.erb`.
  - Optional config: `MAPBOX_STYLE`, `MAPBOX_STYLE_STATS`, `MAPBOX_DATA`, `MAPBOX_DEFAULT_COLOR`.

**Observability:**
- Sentry - Rails, Sidekiq, browser error tracking, and optional tracing/profiling.
  - SDK/Client: `sentry-ruby`, `sentry-rails`, `sentry-sidekiq` in `Gemfile`; Rails init in `config/initializers/sentry.rb`; browser init in `app/assets/javascripts/sentry.js.erb`; React error boundary in `app/javascript/utility/ErrorBoundary.jsx`.
  - Auth: `SENTRY_DSN`; sampling/env via `SENTRY_TRACES_SAMPLE_RATE`, `SENTRY_PROFILES_SAMPLE_RATE`, and `SENTRY_ENVIRONMENT`.
- Lograge - Structured request logs.
  - SDK/Client: `lograge` configured in `config/initializers/lograge.rb`.
  - Auth: Not applicable.
- Barnes/Vernier/rack-mini-profiler/stackprof/memory_profiler/flamegraph - Runtime metrics/profiling dependencies.
  - SDK/Client: `Gemfile`; Sentry profiling uses `vernier` in `config/initializers/sentry.rb`; Puma starts Barnes in `config/puma.rb`.
  - Auth: Not applicable.

**Content Embeds & Metadata:**
- OEmbed providers - Rich embeds for third-party content.
  - SDK/Client: `ruby-oembed`; provider registration is in `config/initializers/oembed.rb`; embed model code lives under `app/models/link_expansion/`.
  - Auth: Optional provider URL from Rails encrypted credentials referenced in `config/initializers/oembed.rb`.
  - Providers explicitly registered: amCharts, Knight Lab StoryMap/Juxtapose/Timeline, Social Explorer, Sketchfab, Google Data Studio, Observable, Crowdsignal, Matterport, and optional naive provider patterns for ArcGIS, Plotly, and Shinyapps.
- OpenGraph metadata - Default previews for links.
  - SDK/Client: `opengraph_parser`; implementation under `app/models/link_expansion/`.
  - Auth: Not applicable.
- Wikidata SPARQL - Researcher, software, hardware, grants, and works metadata lookup.
  - SDK/Client: `sparql-client`; service class is `app/services/wikidata.rb`; HTTP-facing controller is `app/controllers/sparql_controller.rb`.
  - Auth: Not applicable.
  - Endpoint: Wikidata Query Service.

**Browser/CDN Assets:**
- Sentry browser CDN - Loaded by `app/views/layouts/application.html.erb`.
  - SDK/Client: Browser bundle script referenced in the layout.
  - Auth: Sentry DSN configured by browser init.
- Polyfill CDN - Browser polyfills loaded by `app/views/layouts/application.html.erb`.
  - SDK/Client: CDN script referenced in the layout.
  - Auth: Not applicable.
- Google Fonts - Print stylesheet imports Source Sans Pro in `app/assets/stylesheets/print.css`.
  - SDK/Client: CSS `@import`.
  - Auth: Not applicable.

## Data Storage

**Databases:**
- PostgreSQL - Primary relational store.
  - Connection: `DATABASE_URL` in `config/database.yml`; AWS deploy builds and injects it in `infra/sst.config.ts`; local Docker defines the Postgres service in `docker-compose.yml`.
  - Client: Rails Active Record with `pg` gem.
  - Schema: `db/structure.sql`; SQL schema format is set in `config/application.rb`.
  - Notable DB features: Active Storage tables, Action Mailbox inbound email table, Ahoy event/visit tables, and `cases_search_index` materialized view in `db/structure.sql`.
- Redis/Valkey - Cache, Sidekiq queue backend, and Action Cable pub/sub.
  - Connection: `REDIS_URL` in `config/initializers/sidekiq.rb`, `config/cable.yml`, `config/environments/development.rb`, and `config/environments/production.rb`.
  - Client: `redis` gem, Sidekiq, Rails cache store, and Action Cable Redis adapter.

**File Storage:**
- Active Storage local disk in development/test.
  - Config: `config/storage.yml`, `config/environments/development.rb`, and `config/environments/test.rb`.
  - Direct upload clients: `app/javascript/packs/file_upload.js`, `app/javascript/edgenotes/editor/Attachment.js`, and `react-activestorage-provider` usages in `app/javascript/`.
- Active Storage S3 in production.
  - Config: `config/storage.yml`; `config/environments/production.rb` sets `config.active_storage.service = :amazon`.
  - Bucket: configured in `config/storage.yml` and referenced in `infra/sst.config.ts`.
  - Auth: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, or ECS task role policy from `infra/sst.config.ts`.

**Caching:**
- Rails Redis cache store in development and production.
  - Config: `config/environments/development.rb` and `config/environments/production.rb`.
  - Namespace: `cache`.
- Application-level stats caching.
  - Examples: `app/services/case_stats_service.rb`, `app/controllers/cases/stats_controller.rb`, and `app/models/ahoy/event.rb`.
- Rack::Attack throttling uses Rails cache.
  - Config: `config/initializers/rack_attack.rb`.

## Authentication & Identity

**Auth Provider:**
- Custom Rails/Devise authentication backed by local `readers` and `authentication_strategies`.
  - Implementation: Devise setup in `config/initializers/devise.rb`; routes in `config/routes.rb`; identity model in `app/models/authentication_strategy.rb`.
  - Password/account mailer: `app/mailers/authentication_mailer.rb`.
- OAuth/LTI identities are normalized through `AuthenticationStrategy.from_omniauth`.
  - Implementation: `app/controllers/authentication_strategies/omniauth_callbacks_controller.rb`, `app/models/authentication_strategy.rb`, `app/models/auth.rb`, and `app/models/reader.rb`.
- LTI launch identities and group enrollment are linked through `LinkerService`.
  - Implementation: `app/services/linker_service.rb`, `app/controllers/catalog/content_items_controller.rb`, and `app/javascript/shared/lti.js`.
- Authorization uses Pundit policies and Rolify roles.
  - Implementation: `app/policies/`, role models, and editor-only Sidekiq Web mount in `config/routes.rb`.
- Development OmniAuth mocking is available.
  - Config: `config/initializers/mock_omniauth.rb`.
  - Env flags: `MOCK_OMNIAUTH`, `LOCALHOST_SSL`.

## CI/CD & Deployment

**Hosting:**
- AWS is the active SST target.
  - Infrastructure: `infra/sst.config.ts`.
  - Web service: `GalaWeb` runs `bundle exec puma -C config/puma.rb`.
  - Worker service: `GalaWorker` runs `bundle exec sidekiq -C config/sidekiq.yml`.
  - Tasks: `GalaMigrate`, `GalaRefreshIndices`, and `GalaWeeklyReport`.
  - Scheduled production tasks: refresh indices every 15 minutes and send the weekly report email.
  - Domains: production and staging domains are defined in `infra/sst.config.ts`.
- Heroku-compatible deployment metadata remains in `app.json`.
  - Addons: Heroku Postgres and Heroku Redis.
  - Buildpacks: Heroku metrics, apt, wkhtmltopdf, vips, nodejs, and ruby.
  - Stack: Heroku 22.

**CI Pipeline:**
- GitHub Actions deploy workflow is `.github/workflows/deploy.yml`.
  - Manual `workflow_dispatch` accepts `stage` (`staging`, `production`) and `action` (`deploy`, `remove`).
  - Uses AWS OIDC, Node 20, `npm ci`, `npx sst install`, and `npx sst deploy/remove`.
  - Production removal is blocked by the workflow.
- Test/CI commands are described by repo instructions rather than a full inspected test workflow file: RSpec, Jest, asset precompile, schema load, and FactoryBot lint.
