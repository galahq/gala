Design section 1: stage and state ownership

One SST app, multiple narrowly classified stages. Every cloud resource has exactly one state owner.

Durable foundations and derived runtimes
shared
Router distribution · imported media/static buckets · SES compatibility
local bootstrap only · protected · retain-all
dev
VPC · RDS · Redis · cluster · dev runtime · dev route
durable · references shared
production
VPC · RDS · Redis · cluster · root route pointer
durable · references shared
↓ references only; never imports again ↓
pr-NNN
ECS web/worker/tasks · PR route · release prefix
ephemeral · references dev + shared
production-blue / green
ECS runtime · candidate health endpoint · release prefix
independent slot state · references production + shared
local-NAME
VPC/Postgres references · DevCommand · Compose bridge
personal state · no durable cloud ownership
Routing ownership

shared owns the router distribution and DNS attachment.

dev owns only dev.learngala.dev/.

pr-NNN owns only its matching PR route.

production owns only learngala.dev/ and its active-slot pointer.

Hard invariants

One state owner per mutable resource.

Derived stages use get, never a second import.

Preview cleanup cannot address another stage.

Foundation changes require explicit operator intent.

Shared removal is not exposed through routine CI.
