Simplified release versioning

One auto-incremented key is the release identity everywhere. Everything else is derived or looked up.

Canonical key
v412

v + GITHUB_RUN_NUMBER from the single deploy workflow

Automatic increment · unchanged on retry · collision checked

ECR
gala:v412

Immutable tag

ECS pins its digest
S3 assets
releases/v412/

Derived path

No stored prefix field
ECS
gala:release=v412

Task-definition tag

Exact rollback lookup
Complete immutable record
{
  "version": "v412",
  "commit": "2b808a57…",
  "digest": "sha256:…"
}

No release ID, timestamp key, image-tag field, asset-prefix field, or task-definition ARNs.

Complete channel file
{
  "current": "v412",
  "previous": "v411"
}

Updated only after health. Rollback finds the ECS revisions tagged v411.

Retry and promotion behavior

Retry run 412: reuse v412; existing artifacts must match the same commit.

Promote: promote:v412; no rebuild and no new release version.

Rollback: rollback selects previous, or rollback:v410 selects a retained version.

Gaps: diff and operations may consume workflow numbers; gaps are valid and require no counter service.
