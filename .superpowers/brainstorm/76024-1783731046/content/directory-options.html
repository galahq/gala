Three ways to split Gala infrastructure

All three can isolate PR previews. The difference is how many SST applications and operator concepts the team must carry.

infra/ ├── sst.config.ts ├── core/ │ ├── context.ts │ ├── policy.ts │ └── outputs.ts ├── stages/ │ ├── dev.ts │ ├── production.ts │ ├── preview.ts │ ├── production-slot.ts │ └── local.ts ├── stacks/ │ ├── shared.ts │ ├── foundation.ts │ ├── runtime.ts │ ├── routing.ts │ └── jobs.ts └── components/ ├── rails-service.ts ├── secrets.ts └── static-assets.ts
Recommended now · lowest operational change

A. One app, modular stages

One thin entry point and one deploy wrapper. State isolation comes from stage names: dev, production, pr-790, production-blue, and production-green.

Pros

  • Incremental migration
  • One provider install
  • Simple operator model

Cons

  • Stage dispatcher must be strict
  • One app name spans several state roles
infra/ ├── apps/ │ ├── foundation/sst.config.ts │ ├── runtime/sst.config.ts │ ├── routing/sst.config.ts │ └── compatibility/sst.config.ts ├── stages/ │ ├── dev.ts │ └── production.ts ├── components/ ├── contracts/ └── package.json
Stronger boundary · medium complexity

B. Multiple SST applications

Foundation, runtime, routing, and Heroku compatibility each have a distinct app name and state namespace.

Pros

  • Best ownership clarity
  • Narrow diffs
  • Independent permissions

Cons

  • More commands and outputs
  • Harder migration
  • More state coordination
infra/ ├── environments/ │ ├── dev/ │ │ └── sst.config.ts │ ├── production/ │ │ └── sst.config.ts │ └── preview/ │ └── sst.config.ts ├── modules/ │ ├── foundation/ │ ├── runtime/ │ └── routing/ └── operations/
Maximum separation · highest complexity

C. Environment roots

Terraform-style roots make each environment physically obvious and independently runnable.

Pros

  • Very explicit commands
  • Easy environment permissions
  • Small root configs

Cons

  • Configuration drift risk
  • Repeated setup
  • Largest refactor
Why A is the practical first move

It cuts the 827-line config into testable modules without changing the repository's basic SST invocation. If the single-app dispatcher later becomes a constraint, the same stage and stack modules can move into option B with little rewrite.
