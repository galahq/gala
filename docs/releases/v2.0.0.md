# v2.0.0 WIP

This WIP release tracks the AWS/SST `.dev` migration and workflow simplification.
It is scoped to `learngala.dev`, `dev.learngala.dev`, and
`*.dev.learngala.dev` only. The existing `https://www.learngala.com` Heroku
production path is not part of this release unless a later cutover phase says so.

## Scope

- Establish explicit AWS/SST `dev` and `production` environments for the `.dev`
  domain family.
- Support ephemeral pull-request preview environments under
  `*.dev.learngala.dev`.
- Consolidate GitHub Actions to three ARM-runner workflows: `ci`, `deploy`, and
  `infra`.
- Keep `deploy` as the site-operator path with only `stage` plus optional
  `user_data`.
- Keep `infra` as a manually dispatched thin SST wrapper for `diff` and `deploy`
  with a preview checkbox.

## WIP Changes

- Rename/simplify workflow files to `.github/workflows/ci.yml`,
  `.github/workflows/deploy.yaml`, and `.github/workflows/infra.yml`.
- Standardize workflow names and job IDs to `ci`, `deploy`, and `infra`.
- Pin workflow jobs to the ARM GitHub runner `ubuntu-24.04-arm`.
- Preserve the CI validation artifact as advisory evidence while making release
  readiness explicit.
- Document the `.dev` domain, explicit environment, and PR preview boundaries.

## Release Gates

- `ci` evidence is reviewed for required-suite failures and release readiness.
- `infra` preview/diff is reviewed for infrastructure drift before mutation.
- `deploy` is exercised for `dev` before any `production` stage operation.
- Preview host behavior is verified for the relevant pull request under
  `*.dev.learngala.dev`.
- No `.com` or Heroku production mutation occurs as part of this release.

## GitHub release checklist

1. Keep this file marked WIP until the `.dev` workflow migration is validated.
2. Confirm the three-workflow inventory and ARM runner contract.
3. Attach the final `ci` artifact, `infra` diff evidence, and deploy summary.
4. Record the exact `.dev` hostnames validated for dev, production, and preview.
